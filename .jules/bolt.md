## 2026-02-13 - Python Timsort vs Pandas sort_values
**Learning:** Removing a seemingly redundant Pandas `sort_values` step before passing data to a function that uses Python's `list.sort(key=...)` surprisingly *slowed down* the application (from 1.88s to 2.59s for 300k rows). Pandas C-level vectorized sort is much faster than Python's `list.sort` when a custom python function is used as the key. Because Timsort is O(N) on already-sorted data, doing `pandas.sort_values()` followed by a "redundant" `list.sort()` is significantly faster than doing just `list.sort()` on random data.
**Action:** Do not remove Pandas sorting steps to "avoid double sorting" if the downstream function uses Python sorting with a custom key function. The dual sort is actually a codebase-specific performance pattern that works best.

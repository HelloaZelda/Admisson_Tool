## 2024-05-24 - CSV/Formula Injection in Excel Exports
**Vulnerability:** User-controlled strings (like student names or IDs) were being directly written to an Excel file export using `openpyxl.Workbook.append()`.
**Learning:** Even desktop applications are vulnerable to CSV/Formula Injection if they export user-controlled data to Excel formats (`.xlsx` or `.csv`) without escaping characters that could trigger formulas (e.g. `=`, `+`, `-`, `@`, `\t`, `\r`, `\n`).
**Prevention:** Always sanitize user input in all spreadsheet/CSV exports by prepending a single quote (`'`) to strings that start with formula-triggering characters.

## 2026-09-18 - CSV/Formula Injection via Numeric-Sounding Fields
**Vulnerability:** The application exports user-controlled data to Excel and is susceptible to CSV/Formula Injection via numeric-sounding fields (like IDs or sequence numbers, e.g., `序号` or `录取专业`) that are parsed as arbitrary strings from untrusted inputs.
**Learning:** Even fields that are semantically "numeric" or generated by the system (like IDs or major names) can be manipulated if imported from untrusted sources without validation, leading to CSV injection when exported back to Excel.
**Prevention:** All user-controlled strings exported to spreadsheets must be sanitized, explicitly including numeric-sounding fields. Use the `sanitize_excel_input` helper function (which prepends a single quote `'` to values starting with `=`, `+`, `-`, `@`, `\t`, `\r`, or `\n`).
